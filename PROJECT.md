# PROJECT.md — паспорт проекта (читать перед любой правкой)

Этот файл общий для всех, кто работает с кодом: человек, Claude, ChatGPT/Codex.
Если после правки что-то в этом файле устарело — обнови его в той же правке.

## Что это
«Мопс на Манхэттене» — мобильная аркада (портретная ориентация, управление пальцем).
Мопс внизу экрана, сверху падает еда. Ловишь вкусное, избегаешь овощей и кирпичей.
Это скетч-концепт. Планы: сначала PWA на iPhone по ссылке, потом 3D-версия, потом приложение в App Store.

## Как запустить
- Просто открыть `index.html`, либо `python3 -m http.server` в корне и открыть http://localhost:8000
- Публикация: GitHub Pages из ветки `main`, корень репозитория. Все пути относительные (`./`) — не менять на абсолютные.

## Технические правила
- Только обычные скрипты: без npm, без сборщика, без ES-модулей. Всё в глобальной области видимости.
- **Порядок подключения скриптов в `index.html` важен** (`balance.js` первым, `render.js` последним). Новый файл — добавлять в нужное место и упомянуть здесь.
- Логические размеры сцены: около 390×844 (`W`, `H` в `game.js`), реальное разрешение canvas масштабируется по `devicePixelRatio` (потолок в `BALANCE.frame.maxDpr`).
- Весь игровой баланс — только в `js/balance.js`. Числа не хардкодить в других файлах.
- Интерфейс и тексты — на русском.
- Настройки и рекорд хранятся в `localStorage` под ключом `manhattan-pug-progressive` — не переименовывать без миграции.
- Звук синтезируется через WebAudio (`audio.js`), файлов звука нет. На iOS звук стартует только после касания (`unlockAudio`).
- Проверять на мобильном размере (390×844, тач) и в портретной ориентации; горизонтальная есть, но вторична.

## Файлы
| Файл | Что внутри |
|---|---|
| `js/balance.js` | Вся настройка: очки, «счастье», сложность, шансы, длительности бонусов, ритм волн |
| `js/game.js` | Состояние (`state`: menu / play / …), главный цикл логики, спавн еды, ввод (pointer, клавиатура), меню, HUD |
| `js/run-state.js` | Состояние забега: самочувствие мопса, комбо, near-miss, обратная связь |
| `js/powers.js` | Бонусы (магнит, щит, x2, помощники-коты и птицы и др.) |
| `js/events.js` | События: дождь из еды, цепочки, волны, дебаффы (заморозка, ветер и т.д.) |
| `js/audio.js` | Звук и музыка (WebAudio) |
| `js/render.js` | Кадр: порядок отрисовки и `requestAnimationFrame` |
| `js/drawing.js` | Мелкие помощники рисования (ellipse, path, rect…) |
| `js/characters.js` | Рисование мопса, людей, машин, котов |
| `js/food.js` | Рисование еды |
| `js/world.js`, `js/world-details.js` | Рисование города, фона, атмосферы |
| `style.css` | Интерфейс поверх canvas (меню, HUD, панели) |

Типы еды (индекс в `BALANCE.food`): 0 сосиска, 1 печенье, 2 куриная ножка, 3 пончик, 4 брокколи, 5 морковь, 6 цветная капуста, 7 косточка (бонус), 8 кирпич. Вредные: 4–6 и 8 (`isHazard`).
Каждый предмет в массиве `items`: координаты `x`, `y` в логических пикселях, `type`, плюс служебные поля.

## Известное архитектурное ограничение (важно для 3D)
Вся графика нарисована вручную через Canvas 2D и не переносится в 3D.
Логика и отрисовка перемешаны: функции `draw*` лежат в `powers.js`, `events.js`, `run-state.js` рядом с логикой.
Перед 3D нужно разделить: логика (состояние, столкновения, спавн) отдельно, отрисовка отдельно.

## Правила совместной работы (человек + несколько ИИ)
- `main` всегда рабочая: игра открывается и играется. Прямых больших правок в `main` нет.
- У каждого исполнителя своя ветка: `claude/<тема>`, `chatgpt/<тема>`. Слияние через pull request.
- Один файл не правят двое одновременно. Перед большой задачей — написать в PR/чате, какие файлы затронешь.
- Правки — маленькие и точечные. Не переформатировать файлы целиком и не переименовывать без причины: это ломает слияние.
- Не менять баланс «по ходу» вместе с другой задачей: баланс — отдельным коммитом.
