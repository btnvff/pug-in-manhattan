# Мопс на Манхэттене

Портретная браузерная игра: двигайте мопса по улице, ловите еду, избегайте вредных предметов и набирайте очки. Город и персонажи построены программно; внешние изображения, аудиофайлы и CDN не нужны.

## Play

[Играть на GitHub Pages](https://btnvff.github.io/pug-in-manhattan/)

Игра использует только Three.js 3D и требует WebGL 2. Pages показывает опубликованную ветку `main`, а не произвольную рабочую ветку.

## Controls

Перетаскивайте нижнюю часть игрового поля пальцем или мышью. На клавиатуре используйте **← / →** или **A / D**; фокус не должен оставаться на кнопке. **Escape** или кнопка «Пауза» приостанавливают забег. «Продолжить» возвращает в игру. Потеря фокуса и скрытие вкладки автоматически ставят игру на паузу. Кнопка динамика включает и выключает звук.

## Features

Three.js-сцена Манхэттена с перспективой, мостом, транспортом и прохожими; анимированный мопс; девять типов предметов; бонусы, коты и птицы-помощники; городские события и синтезированный WebAudio. Баланс, ввод, очки и игровой RNG не зависят от рендеринга. Рекорд и настройки сохраняются локально.

**PUG WORLD RATIO 1.0.0** фиксирует композицию 600 × 1125, перспективу и относительные размеры. При изменении окна композиция целиком вписывается в экран без растяжения, а логические координаты игры остаются прежними.

## Running locally

Из корня репозитория:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000/`. Установка npm-пакетов и сборка для запуска игры не требуются. Все пути относительные и совместимы с GitHub Pages.

Необязательная команда `node scripts/build-preview.js` копирует готовые статические файлы и лицензию Three.js в `dist/`. Это экспорт для размещения, а не обязательный build pipeline; содержимое `dist/` пересоздаётся.

## Architecture

| Ответственность | Основные файлы |
| --- | --- |
| Правила и состояние | `balance.js`, `game.js`, `run-state.js`, `powers.js`, `events.js` |
| Пропуски предметов и помощь котов | `street-events.js` |
| Звуковые графы и их lifecycle | `audio.js` |
| Пропорции и общий город | `world-ratio.js`, `ratio-scene.js` |
| 3D-сцена и экранные эффекты | `render.js`, `render-3d.js`, `render-feedback.js`, `drawing.js` |
| Персонажи и предметы | `pug-3d.js`, `pug-animation.js`, `models-3d.js` |
| Диагностика композиции | `ratio-diagnostics.js` |

Все перечисленные модули находятся в `js/`. Порядок классических `defer`-скриптов задан в [index.html](index.html). Контракты координат, владение ресурсами и правила изменения проекта описаны в [PROJECT.md](PROJECT.md).

## Testing

Тесты логики, геометрии, проекции, событий, структуры репозитория и HTTP-ресурсов запускаются непосредственно в Node.js 22+:

```sh
node tests/run.js
```

Браузерные проверки используют внешнюю установку Playwright и Chromium, не добавляя зависимости игре:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright CHROMIUM_PATH=/path/to/chromium node tests/run.js --browser
```

По умолчанию браузерные тесты работают через локальный HTTP-сервер. `OFFLINE_BROWSER=1` явно переключает их на загрузку локального содержимого в настоящий DOM/WebGL; этот режим **не проверяет HTTP-навигацию**. На Linux без дисплея для software WebGL может понадобиться `xvfb-run -a`. `SCREENSHOT_DIR=/path/to/output` сохраняет снимки основных браузерных сценариев. `node tests/run.js --all` запускает оба набора; ошибки окружения не скрываются как успешные тесты.

Для точного сравнения с доступным Git-коммитом:

```sh
node tests/gameplay.test.js --compare <git-ref>
```

## Browser support

Нужен современный браузер с WebGL 2. При отсутствии WebGL, ошибке инициализации, рендера, resize или потере контекста игра останавливается и показывает сообщение «3D-графика недоступна» с кнопкой перезагрузки. Незаметного переключения графики или игры на пустом экране нет. Перезагрузка начинает новый сеанс; рекорд и настройки сохраняются.

Canvas используется только для прозрачных экранных эффектов, ввода и текстур 3D-сцены, не как отдельная версия игры.
